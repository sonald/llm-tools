## 1. 产品决策

将产品默认体验定义为：**打开后读懂内容，需要时查看结构，随时回到精确原文。**

不再让使用者先理解 Document / Collection / Entry、Node ID、字节区间、语义投影、候选项和词法单元，才能完成阅读。

保留本地、只读、精确原文、大文件有界加载和安全隔离的底层设计。不为改善视觉而使用普通 JSON.parse / JSON.stringify 取代现有源数据模型；重复键、数字词法形式、字符串转义和原始顺序必须保留。

### 1.1 核心界面关系

- 左侧：导航。普通 JSON 提供真实的内容大纲；记录文件提供记录列表及当前记录的大纲入口；已识别会话可提供消息目录。
- 中央：`阅读 / 源文本`。两者是**相同阅读范围**的不同表示。
- 右侧：按需打开的字段详情。显示选中字段的内容、复制操作和可展开的来源细节，不长期占据阅读空间。
- 完整结构检查仍可用，可作为扩大导航区或独立结构视图的专业入口，不必在第一阶段删除中央 Tree。
- “所选字段的原始 JSON”是字段详情，不应冒充“当前文件／记录的源文本”。

### 1.2 不变式

1. 切换表示方式，不改变阅读范围。
2. 选择树节点，不改变阅读范围；只改变焦点及定位。
3. 选择另一条记录或执行“单独阅读此字段”，才改变阅读范围。
4. 搜索范围必须可见且明确，不根据隐藏组件的内部状态悄悄变化。
5. 未识别出会话不等于没有可读内容，合法 JSON 必须有通用阅读回退。
6. 自动识别不能抢走用户已经主动选择的阅读位置或表示方式。
7. 数据缓存淘汰不等于用户导航状态丢失。
8. 所有渲染内容都能追溯至源位置；嵌套解码范围不冒充原文件字节范围。

## 2. 当前功能与触发条件

| 功能 | 当前实现中的条件 | 对用户的影响 |
| --- | --- | --- |
| 左侧 JSONL 列表 | 文件进入 Entry 模式，索引建立后展示记录 | 普通 JSON 不走这条路径 |
| 左侧数组列表 | JSON 根为数组，进入 Collection 模式 | 普通对象根没有相同的大纲组件 |
| 普通 JSON 大纲 | 页面提供“大纲按需加载”的状态文案，但没有挂载对应的文档大纲组件 | 用户等待或猜测操作也无法得到承诺的大纲 |
| 会话阅读 | 当前范围本身为数组，或当前范围对象的直接字段 messages / conversation / conversations 为数组，再通过候选识别 | 不是任意 JSON 的通用阅读器，也不是递归识别所有嵌套消息 |
| 候选选择 | 多个候选或可能的候选需要用户操作；唯一明确候选在直接字段扫描完成后可自动选中 | 必须解释“选择的是哪个消息数组” |
| 字符串丰富阅读 | Tree 选择字符串后预览，或双击字符串，进入 Content Viewer | 产品的重要阅读能力隐藏在辅助对话框里 |
| Raw | 树选择通过 setScope 缩小至节点；搜索／会话通过 revealRange 返回 baseScope 并定位 | 同一标签含义因入口不同而变化 |
| 搜索 | 左侧记录搜索、中央当前范围搜索、Content Viewer 搜索各自存在 | 不同作用范围和表示选项需要统一表达 |
| 复制 | Tree 的 Raw 和 JSON Subtree 按钮都使用 copySelected("raw", ...) | 用户面对两个名称不同但行为相同的选择 |

## 4. 目标工作台

```text
文件名.jsonl   JSONL · 1,204 条记录（扫描完成后显示总数）   只读   搜索   文件信息
────────────────────────────────────────────────────────────────────────────
导航                     文件 > 第 18 条记录                 返回 / 前进
                         阅读 | 源文本                       字段详情（开关）
───────────────────────┬────────────────────────────────────────────────────
搜索记录…              │ 当前记录：工具调用与结果
                       │
第 17 条  assistant…   │ assistant
第 18 条  tool…        │ 可直接阅读的文字、Markdown 和代码
第 19 条  user…        │
                       │ 工具：read_file
当前记录大纲           │ 输入：…              输出：…
  role                 │
  content              │ [展开阅读]  [复制文本 ▾]  [查看数据]
  metadata             │
───────────────────────┴────────────────────────────────────────────────────
当前范围：第 18 条记录  · 本地只读 · 按需加载状态
```

图示为信息结构示意，不是经过渲染验收的视觉设计。

### 4.1 左侧导航规则

普通 JSON 对象：打开后显示根及第一层字段，深层按需展开，不再输出占位的大纲承诺。根标量显示根值／类型，不伪装成空文档。

普通 JSON 数组或 JSONL 数据集：显示记录列表，优先采用现有摘要能力。源字节位置不出现在每个记录的主摘要中。当前记录的大纲可在同一侧栏切换或作为可展开区，不同时堆砌两棵完整结构树。

根数组被高置信度识别为一段会话：默认展示整个会话，而不是把每条消息强行当成彼此独立的数据集记录。识别不确定时保留通用浏览，并允许显式“按消息阅读”。

JSONL 事件摘要不等于跨记录会话聚合。首轮保留逐条阅读，不凭 event hint 宣称能自动还原整段 Agent 会话。

### 4.2 通用阅读器规则

- 对象：以字段名、值和必要类型组织；长文本可展开；未识别字段仍可见。
- 数组：展示长度、条目摘要和可访问的元素；不一次展开所有元素。
- 字符串：正常显示解码后的文本；适当识别 Markdown、代码或嵌套 JSON；保留原始 JSON 字符串入口。
- 数字：来自保留词法信息的源数据，不经过 JS Number 重新生成。
- true / false / null：明确显示值，不能因布尔判断而被当作无内容。
- 空对象、空数组、空字符串：分别标示，不使用同一个“暂无数据”。
- 长内容：显示实际预览范围和继续读取动作；不让截断摘要伪装成完整内容。
- 会话：使用现有 ConversationView 专用投影；消息 role、正文、工具输入输出优先，原始来源动作收进上下文操作。

### 4.3 源文本与所选字段详情

主源文本：同一个 ReaderScope 的原始词法内容，选择字段时滚动定位并高亮，不替换为仅此字段。

字段详情：显示当前 FocusTarget 对应的字段和值，可以直接查看局部原始 JSON。面板标题必须写出字段路径，避免与主源文本混淆。

技术详情折叠区：Node ID、源字节区间、文件／记录／嵌套坐标系、解析诊断、会话修订标识。日常阅读隐藏，但诊断和源追踪仍然完整。

“源文本”不默认重新格式化。以后增加格式化功能时，应标明是派生表示，并使用保留顺序、重复键、数字词法形式的 token 级格式化；不能把重新序列化结果称为原始文本。

## 5. 状态与事件设计

### 5.1 状态概念

| 状态 | 回答的问题 | 谁能改变 |
| --- | --- | --- |
| ReaderScope | 当前读整份文件、哪条记录，还是显式聚焦的子树？ | 打开文件、选择记录、单独阅读字段、返回历史 |
| FocusTarget | 当前范围内正在关注哪个字段、消息或搜索命中？ | 树选择、正文点击、搜索定位 |
| Representation | 当前以阅读还是源文本呈现？ | 标签／视图控制 |
| DisplayOverride | 当前内容是否手动按 Markdown／代码／指定消息格式解读？ | 局部格式控制 |
| CapabilityState | 当前可用、扫描中、不适用、超限还是失败？ | 数据和识别服务 |

建议使用明确的 SourceRef，包含文件身份与版本、记录／嵌套 scope 身份、节点及来源位置。JSON Pointer 用于展示，不作为重复键场景的唯一身份。嵌套字符串的解码坐标不直接当成文件字节坐标。

### 5.2 事件契约

| 操作 | ReaderScope | FocusTarget | Representation |
| --- | --- | --- | --- |
| 点击树字段 | 不变 | 该字段 | 不变 |
| 从阅读切换源文本 | 不变 | 保留 | source |
| 点击“查看该字段的原始 JSON” | 不变 | 该字段 | 主阅读区不变；打开局部详情 |
| 点击“单独阅读此字段” | 变为显式子树 | 子树根 | 保留适用视图 |
| 选择另一条记录 | 变为该记录 | 恢复历史或记录根 | 保留；必要时明确回退 |
| 当前记录内搜索命中 | 不变 | 命中节点／位置 | 尽量保留，回退必须解释 |
| 全文件搜索命中其他记录 | 显式进入命中记录 | 命中节点 | 保留适用表示 |
| 返回 | 恢复历史 | 恢复历史 | 恢复历史 |

避免再由 `handleTreeSelection` 直接修改 Raw 的数据范围。应该更新共享焦点，再由 SourceView 在固定 ReaderScope 中定位。

### 5.3 状态保存与生命周期

- 按逻辑范围保存树展开状态、选择、滚动锚点、会话候选和用户格式选择。
- 缓存可被 ProjectionBudget 淘汰；逻辑位置用轻量状态保留，返回后按需重载。
- 文件被外部修改时，旧 SourceRef 不再可用。提供重新加载，并在重新验证后尽力恢复逻辑位置，不能盲用旧字节偏移。
- 异步识别完成不自动切走用户正在看的源文本，也不覆盖手动选择的格式。
- JSONL 索引继续增长时不抢焦点、不覆盖用户已经选中的记录。

## 6. 控件与文案规范

| 当前概念 | 用户需要理解的含义 | 建议名称／呈现 |
| --- | --- | --- |
| Semantic | 可读内容的呈现方式 | 阅读 |
| Tree | 字段结构及定位 | 内容大纲／结构检查 |
| Raw | 当前范围精确原文 | 源文本；首次补充“原始 JSON” |
| Conversation candidate | 哪个数组是消息列表 | 消息数组；显示路径、数量和首条摘要 |
| Render As OpenAI/Anthropic style | 按哪种消息格式解释 | 消息格式：自动／通用／OpenAI／Anthropic |
| Scan more direct fields | 已检查范围尚不完整 | 继续查找消息数组；同时显示已检查范围 |
| Wrapper Raw/Tree | 会话外层完整数据 | 查看完整数据；子菜单选择结构／源文本 |
| Raw Lexeme | JSON 中保留引号及转义的写法 | 原始 JSON 字符串 |
| Decoded Value | 去除 JSON 包装后的实际字符串 | 文本内容 |
| Detection source / Plain reason | 自动识别结论及为何未渲染 | 识别详情；默认收起 |
| Copy Raw / JSON Subtree | 复制相同的原始节点片段 | 合并为复制原始 JSON |
| Copy Decoded | 复制真实字符串文本 | 复制文本 |
| Scope Search | 在明确对象范围内寻找内容 | 查找 + 可见范围选择 |
| Page/block cursor | 继续读取的当前位置 | 下一组消息／继续读取文本；不要只显示内部块数 |

### 6.1 会话控件

只有相关时显示会话格式和消息数组选择器。明确已识别来源，例如“消息来自 $.messages · 24 条消息 · 格式：自动识别为 OpenAI”。

存在多个候选时，让用户选择消息数组，不要求理解 candidate kind 或 Node ID。存在可能的会话时提供“尝试按会话阅读”，并允许返回普通 JSON 阅读。

手动切换格式只影响当前范围，保留原始数据和其他字段；有明确的“恢复自动”。恢复位置优先使用源节点／消息身份，而不是旧页面序号。

### 6.2 内容格式控件

在字段或独立阅读器附近显示“格式：自动（Markdown）”，不把十几种语言选项无差别铺给所有字符串。代码语言作为次级选项。

表示关系分清：阅读效果、实际文本、原始 JSON 字符串。对纯文本不强行展示三份看起来重复的标签。

HTML 仍在隔离容器内阅读，不能因为改为内联而取消沙箱、净化或网络限制。

### 6.3 复制规范

默认动作按内容决定，例如普通字符串“复制文本”，结构节点“复制原始 JSON”。下拉菜单提供其他表示。

复制反馈明确“复制了什么、范围是什么”。完整复制超出限制时给出限制与可用替代，不静默只复制可见部分。后续若增加“复制已选文本／预览内容”，应单独命名。

## 7. 搜索设计

统一 Find 交互语言，但不要求把三种后端搜索实现合成一个巨大接口。

- 入口：常用快捷键和可见查找按钮。
- 范围：本文件／当前记录／当前字段，当前范围始终可见。
- 默认：搜索可读内容，包括可搜索的键和值。
- 高级：在原始 JSON 中搜索、通配符、只显示匹配记录等。
- 展示：当前命中位置、已发现数量、是否仍在扫描，不把未扫描误报为无结果。
- 定位：消息正文、字段文本、结构、源文本依能力选择，不一律把用户带到 Raw。
- 转义：解码命中的字符范围不直接等于原文的字节范围。无法精确映射时定位到字段，并解释是在源文本中查看整个字段。
- 大文件：保持增量扫描、取消、预算和分页。范围扩大到全文件时必须明确告知。

## 8. 空状态、降级与恢复

| 状态 | 用户看到的内容 | 必须可执行的下一步 |
| --- | --- | --- |
| 未打开文件 | 打开／拖入本地文件说明，说明只读 | 打开文件 |
| 普通 JSON，无会话 | 正常的通用阅读内容 | 查看结构；必要时选择消息数组 |
| 候选扫描尚未结束 | 已检查范围、扫描状态，仍能读普通内容 | 继续查找／取消／手动选择数组 |
| 可能的会话 | 普通 JSON 仍可读，提供尝试提示 | 尝试按会话阅读／保持普通阅读 |
| 多个会话数组 | 路径、数量、摘要 | 选择一个消息数组 |
| JSONL 索引未完成 | 已发现记录并可读，总数标为未知／扫描中 | 选择记录；停止搜索不等于删除索引 |
| JSON 无法解析 | 源文本及诊断 | 定位问题；重新加载；必要时更换打开方式 |
| 非 UTF-8 | 清楚标记有损显示；提供十六进制 | 切换显示；查看编码说明 |
| 超大字符串 | 可读预览、实际限制 | 继续读取；使用可用的源文本搜索 |
| 文件已修改 | 暂停旧定位并解释原因 | 重新加载 |
| 空对象／数组／字符串 | 分别显示具体的空值 | 源文本和适用复制仍可用 |

原则：空状态是当前状况、原因和下一步，不是只有“不可用”或“尚未加载”。

## 9. 分阶段落地

### 阶段 A：修正范围与死胡同（P0）

主要文件：`main.ts`、`raw-view.ts`、`index.html`、`tree-view.ts`、`style.css`、`i18n/*`。

1. 明确 ReaderScope 与 FocusTarget，先切断树选择对主 Raw 范围的隐式替换。
2. Raw 使用固定阅读范围 + reveal；局部原文独立命名。
3. 无会话时默认结构回退，解析失败时默认源文本，不等待完整 GenericReader 才消除死胡同。
4. 删除“大纲按需加载”的虚假承诺；真实大纲就绪前收起无用栏并提供结构入口。
5. 默认隐藏树行 Node ID 与字节范围，合并同义复制按钮。
6. 为文件修改、解析失败和当前范围加载失败增加实际恢复按钮。
7. 桌面检查器可折叠，避免空栏常驻。

交付标准：同一文件／记录内切换标签不会悄悄改变数据范围；任何已打开且有可读字节的文件都不会仅停在无用 Semantic 空页。

### 阶段 B：建立“打开即可阅读”的主体验（P1）

建议新增模块：`generic-reader.ts`、`document-outline.ts`（优先复用 TreeView 的数据与虚拟化能力）、`reader-capabilities.ts`。

1. GenericReader 支持所有 JSON 基本类型，保留所有字段，不做隐式丢弃。
2. 文档大纲真实加载，记录文件复用现有摘要与导航能力。
3. 集成已有字符串渲染器，增加“展开阅读”；保留大内容独立阅读入口。
4. 记录文件选择首条可用记录；不跳过损坏记录；根会话数组保持整段阅读。
5. 会话成为阅读器能力，不再占据唯一的默认入口。
6. 提供明确的消息数组选择入口；深层路径通过显式选择支持，避免无界自动递归识别。

交付标准：普通配置 JSON、包含长字符串的对象、根会话数组和普通 JSONL 均能不读帮助完成阅读。

### 阶段 C：统一搜索、详情与阅读历史（P1）

建议新增／提炼：`reader-state.ts`、`navigation-controller.ts`、`selection-inspector.ts`、`search-controller.ts`。

1. 引入跨范围的返回／前进和轻量快照。
2. 搜索界面统一范围与表示，结果遵循 FocusTarget 协议。
3. 字段详情追踪选择但不强迫打开，原文显示明确标注局部范围。
4. 将候选选择、消息格式、文本格式改成作用范围清晰的局部控件。
5. 将三个中央标签逐步收敛为“阅读／源文本”；保留完整结构检查入口。
6. 内容对话框减少常驻诊断元数据，提供一致的复制和格式选择。

交付标准：从某条记录的正文查找到工具参数，查看原始 JSON，再返回时，用户的位置、范围和理解没有丢失。

### 阶段 D：验证真实任务，不只验证组件存在（P2）

1. 保留并运行已有回归与性能测试。
2. 添加以下任务矩阵及必要测试 fixture。
3. 在原生 macOS 实机捕获各关键状态；验证窗口缩放、字体、键盘、焦点和屏幕阅读器行为。
4. 大文件改造不得取消分页、预算、请求取消、会话版本校验和安全隔离。
5. 发布材料和 README 只承诺已实际可用的能力，不将内部模型名当成操作指南。

## 10. 验收测试矩阵

以下是拟定验收标准，不表示本次已经执行通过。

| 编号 | 输入／任务 | 通过条件 |
| --- | --- | --- |
| A01 | 普通对象 JSON，无 messages 字段 | 首屏有真实字段大纲与可读内容；没有无动作的语义空页 |
| A02 | `{}`、`[]`、`""`、`null`、`0`、`false` | 六种值分别正确显示，不把 false 或 0 当无数据 |
| A03 | 对象里有长 Markdown／代码字符串 | 无需知道双击规则即可发现并打开可读内容 |
| A04 | `payload.messages` 或自定义 history 数组 | 普通阅读可用；显式选择消息数组可以到达目标；未自动发现不称为没有数据 |
| A05 | 根为消息数组 | 默认整段会话，不只阅读第一个消息对象 |
| A06 | 多个候选、可能候选、混合格式 | 有路径、摘要和明确选择；切换解释方式能撤回；不丢弃原数据 |
| A07 | JSONL 开始索引 | 首条记录出现即可读；总数未知时不假报总数；继续索引不抢当前选择 |
| A08 | JSONL 第一条损坏 | 不静默跳过；显示错误和该条原文，后续条目仍可导航 |
| A09 | 树选择深层字段后切换源文本 | ReaderScope 不变；字段被定位；整条记录仍可浏览 |
| A10 | 对字段执行单独阅读，然后返回 | 面包屑变化明确；返回恢复原 scope、焦点、表示和位置 |
| A11 | 从会话／结构／搜索分别查看同一字段源文本 | 主源文本具有一致范围，字段详情与整条记录原文不混淆 |
| A12 | 搜索文本含 JSON 转义或 Unicode | 解码搜索和原文搜索结果准确；不能精确映射时不伪造原文字节高亮 |
| A13 | 全文件搜索仍在扫描 | 显示部分结果与未完成状态；取消有效；不能把未知范围计为无结果 |
| A14 | 重复键、大整数、转义字符串 | 结构与原文保留每次出现及数字原写法；复制原始 JSON 不经普通对象重序列化 |
| A15 | 复制字符串文本 vs 复制原始 JSON | 前者去掉 JSON 引号并解释转义；后者保留；反馈名称准确 |
| A16 | 在分页或预算淘汰后返回原记录 | 逻辑展开、选择和阅读锚点恢复；允许重新加载数据 |
| A17 | 切换会话解释格式 | 尽量保持同一消息；不能保持时明确告知，而非无提示跳回开头 |
| A18 | 文件被外部修改 | 旧定位与复制被安全阻止；有可执行重新加载；不盲用旧 span |
| A19 | 无效 UTF-8／不可解析 JSON | 有损文本明确标记，十六进制仍可访问；原文件不被修改 |
| A20 | 超大 JSON、长文本、大量记录 | 保持有界内存、虚拟化、分页与异步过期检查；性能以现有基线实测，不凭设计宣称 |
| A21 | 键盘完成打开、导航、搜索、查看字段、返回 | 每个动作可达；焦点与选择语义清楚；对话框关闭后焦点合理恢复 |
| A22 | 小窗口、中文长文案、200% 缩放 | 核心内容和操作可达；没有被固定面板挤掉的关键动作；需实机截图验证 |
| A23 | 恶意 HTML／Markdown 输入 | 不执行不可信脚本，不发起未允许网络、导航或应用 IPC；沿用并实测既有隔离策略 |
| A24 | 用户已切源文本，后台会话识别刚完成 | 不能自动抢回会话阅读；只提供可发现的切换机会 |

### 10.1 最小真实用户任务

让未读说明的使用者打开一个普通 JSON、一个训练样本 JSONL、一个含工具调用的会话文件，完成：找到指定字段／消息，展开长文本，复制实际文本，查看同一位置的原始 JSON，再返回原位置。

记录首屏是否有可读内容、完成过程是否需要外部解释、是否出现错误的范围理解、是否复制了错误的表示，以及回退是否丢失上下文。所有目标是设计验收要求，不是已测量的提升幅度。

## 11. 保留的已有能力

不是全盘重写。以下能力应继续复用：

- 源字节与节点定位、重复键支持和原始数字／字符串表示。
- JSONL 索引、记录摘要、数组列表、分页与虚拟化。
- TreeView 已有键盘操作、ARIA、焦点处理、快照和局部返回能力。
- Content Viewer 的现有文本／Markdown／代码／HTML／嵌套 JSON 渲染与复制能力。
- 错误状态、重试、复制反馈、部分内容提示，以及请求版本／过期检查。
- ProjectionBudget、安全净化、HTML 沙箱、禁止网络和应用 IPC 的限制。

改造重点是把这些能力放到合适的任务关系中，而不是继续增加并列标签和技术控件。
