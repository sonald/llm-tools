# 导航内容搜索：规格与实现计划

状态：设计提案，尚未实现。2026-09-24。

## 1. 判断与目标

合理。浏览数据集时，用户通常知道记录里的内容，不知道记录编号。导航应支持“找到包含某段内容的记录”，同时保留编号定位。

高亮与过滤是同一组匹配结果的两种显示方式：高亮保留上下文，过滤便于连续阅读命中记录。过滤模式也高亮命中证据；切换显示方式不重新搜索。

本次“任意内容”指搜索完整记录中的 key 和值，包括未展开节点、未加载页面和长字符串尾部，不能只搜索列表摘要。“通配”另外明确为可选的 `*`、`?` 模式。

## 2. 当前实现及约束

- `index.html` 左侧只有 Entry / Item 的 Go 输入框；它们是编号跳转，不是内容搜索。
- `entry-list.ts`：JSONL 按 200 条分页，显示编号从 1 开始。
- `collection-list.ts`：根数组按 200 项加载并虚拟滚动，Item 编号从 0 开始。
- `main.ts:currentSearchScope()` / `search-view.ts`：中间已有当前 Document、当前 Item、当前 Entry 搜索；Collection 未选 Item 时可搜索根数组。结果目前通过 `handleSearchReveal()` 定位到 Raw。
- `src-tauri/src/search.rs` 已实现 decoded key/value 和 Raw Source 字面子串搜索。现有限额：query 4096 UTF-8 bytes、50 个匹配/page、8 MiB 扫描预算/page。
- `jsonl_session.rs` 只有当前选中 Entry 的搜索。超过 16 MiB 的 Entry 不建树；非法 JSON / UTF-8 也不能假装具备 decoded 搜索能力。
- `ipc.rs:select_entry_inner()` 会推进 `sessionRevision`。搜索全文件时不能逐条调用它，否则会改变阅读内容并使旧游标失效。
- 前端已有 32 MiB `ProjectionBudget`。禁止把整个文件或所有结果摘要传到 WebView 后过滤。

## 3. 范围与入口

### 3.1 本次交付

| 文件模式 | 导航搜索范围 | 命中单位 |
| --- | --- | --- |
| JSONL / Entry | 整个已打开文件，逐条扫描非空物理行 | Entry |
| 根数组 / Collection | 根数组的全部 Item 及各自完整子树 | Item |
| 对象或标量 / Document | 沿用中间现有 Document 全文搜索 | 本次不新增导航列表 |

Document 目前没有记录列表。本次不把树过滤、Document 搜索重构混入记录导航；若后续要筛选 Document 字段，另定“祖先保留、子树展开、直接命中与后代命中”的规则。

### 3.2 左侧布局

```text
导航 · Entries
[搜索记录内容…                       ×]
[普通文本 ▾] [解码内容 ▾] [搜索]
[高亮全部] [仅看匹配]
已检查 12,800 条 · 已命中 36 条 · 搜索中 [停止]
[上一条匹配] [下一条匹配]

[原有 Entry 列表 / 过滤后的 Entry 列表]

跳转编号 [            ] [跳转]
```

- 搜索输入成为主要入口；编号跳转保留为独立紧凑控件，不混用一套语法。
- 默认普通文本、解码内容、高亮全部。下拉选项分别为“普通文本 / 通配符”和“解码内容 / 原始文本”。
- 输入框提示清楚写“整个 JSONL 文件”或“全部数组项”；中间搜索继续标明“当前 Entry / Item”。两者查询互不覆盖。
- 首版按 Enter 或搜索按钮执行，不逐键扫描整个文件。中文输入法组合阶段的 Enter 不提交。
- 改动查询或搜索选项立即停止旧任务并清掉旧标记，显示“按 Enter 搜索”；显示模式切换即时生效。
- 空查询清除搜索，恢复普通导航；不 trim 查询，单个空格也可以作为合法搜索内容。
- Esc 在搜索框内清除查询；清除按钮可键盘访问。未打开文件时不显示该入口。

## 4. 匹配语义

### 4.1 普通文本

默认区分大小写、按包含关系匹配，保持现有搜索语义。数字输入 `123` 搜索内容，不解释成编号。不做分词、隐式 AND、拼音、语义相似度或 Unicode normalization。

| 数据 | 解码内容模式搜索对象 |
| --- | --- |
| key | 完整解码后的 key；重复 key 分别遍历 |
| string | 完整解码 Unicode 文本，含换行 |
| number | 原始数字 lexeme，不重新格式化 |
| boolean / null | `true`、`false`、`null` |
| object / array | 遍历子节点；不把整棵树重新序列化成一个字符串 |

例如 `你好` 可以命中源文件中的 `"\u4f60\u597d"`。匹配不跨越 key/value、两个字段或两条记录。任意一个字段命中即保留该记录，同一记录只列一次，计数是记录数而不是出现次数。

原始文本模式扫描每条 Entry / Item 的原始 source 范围，允许跨该记录内的标点和换行，但不跨记录边界；JSONL 的换行分隔符不属于记录。它可用于搜索转义文本、非法 JSON、超大 Entry 和非法 UTF-8 中仍能精确匹配的 UTF-8 查询字节。

### 4.2 通配符

仅显式选择“通配符”时解释下列语法：

| 输入 | 意义 |
| --- | --- |
| `error*timeout` | 同一搜索字段中依次出现 error 和 timeout，中间任意长度文本 |
| `user_?` | `user_` 后恰好一个 Unicode 标量值 |
| `*` | 零个或多个 Unicode 标量值，包含换行 |
| `\*`、`\?`、`\\` | 字面星号、问号、反斜线 |

- 使用子串匹配；不要求覆盖整个字段。`?` 按 Unicode 标量值计数，emoji 组合序列可能含多个值。
- 选最左起点的最短成功片段作为该字段的首个证据；按源顺序选择记录中的首个匹配字段。
- 连续 `*` 合并。只有星号的模式拒绝执行并提示输入实际内容，避免零长度匹配把全部记录变成命中。
- 末尾孤立反斜线及其他未定义转义报输入错误；普通文本模式下反斜线不特殊解释。
- 通配模式允许前后空格，不擅自去除。最多 4096 UTF-8 bytes，且解析后最多 256 个模式 token；超限明确报错。
- 非法 UTF-8 的原始文本支持普通文本字节搜索；Unicode 通配搜索跳过这类记录并报告数量，不在 lossy 替换文本上宣称精确匹配。
- 不引入 regex、JSONPath、布尔表达式语言。

## 5. 高亮、过滤与选择

### 5.1 高亮全部

- 保持原始顺序、编号、总行数、滚动几何和分页方式。
- 命中行显示“匹配”标记；能在现有摘要中准确映射的文本使用 `<mark>`，其余显示命中证据提示。
- “尚未检查”与“已检查未命中”可区分，未扫描区域不能被标成无匹配。
- 上/下一条匹配按原始编号导航，不循环；自动选中记录，复用现有加载流程。后方仍在扫描时显示“查找中”，不要提前说已到最后一条。

### 5.2 仅看匹配

- 仅投影命中 Entry / Item；保持源顺序及原始编号，不重新编号。
- 虚拟列表位置是结果序号，选择身份仍是原始 ordinal；严禁把第 3 条结果当成原文件的 Item 3。
- 一条记录无论匹配多少次只显示一次。扫描继续时只在结果尾部追加，不重排已显示结果。
- 扫描中显示“已找到 N 条，仍在搜索”；完成后显示“匹配 N / 共 M 条”。有跳过记录时单列数量。
- 只有完整扫描且没有命中才显示“未找到匹配”；停止、失败、资源上限均显示部分结果。

### 5.3 内容与状态恢复

- 开始搜索、切换模式、结果增长均不自动切换中间阅读内容。
- 当前阅读记录被过滤隐藏时，中间内容保留，提示“当前记录不在匹配结果中”。不向过滤列表额外插入不匹配行。
- 清除搜索后定位当前阅读记录；没有选择则恢复搜索前的原始列表锚点。
- 过滤中按编号跳转：切换到“高亮全部”，按原有语义定位该编号；保留查询和搜索任务，显示切换提示。仍不把“定位”暗改为“选中”。
- 选择 JSONL 结果后文件级搜索保持有效，即使当前 Entry 的 sessionRevision 已变化。
- 搜索结果提供至少一个证据：相对字段路径、key/value/raw 标签、匹配附近的纯文本片段。片段按当前结果页按需加载，不为所有命中保存完整字符串。
- 证据预览放在列表外的详情区，保持原有行高；选中行后可用“查看命中位置”复用 Raw 定位。decoded 模式若不能精确映射到源字符，则定位整个源 token，并明确说明；不伪造逐字符源高亮。
- 大段 glob 命中使用前后文截断和省略号，单条证据最多 256 个 Unicode 标量；没有精确 offset 时只标记行，不根据猜测给字符着色。
- 高亮只用 text node + `<mark>`，不将搜索词或文件内容拼成 HTML。

## 6. 扫描、资源与错误

- 后端扫描完整数据；不依赖 Tree 展开状态、列表页缓存、valuePreview 或摘要长度。
- Collection 复用已解析树，逐 Item 搜索。JSONL 顺序读取并使用现有解析路径产生临时树；不调用选择接口，不替换 selected Entry，也不为全文建立持久索引。
- decoded 模式遇到非法 JSON、非法 UTF-8、超过现有解析上限的 Entry 时跳过并按原因计数，提示可切换原始文本；禁止静默降级造成混合语义。
- JSONL 索引未完成时搜索可以扫描已索引前缀，并等待索引继续推进；“追上索引”不等于“文件搜索完成”。只有索引到 EOF 且扫描到 EOF 才完成。
- 首个版本每文件最多一个导航搜索任务；新查询、清除、关闭或重开文件释放旧任务。文件变化沿用现有失效处理。
- 每次推进最多扫描 8 MiB，并额外检查操作数/时间预算；初始目标为约 20 ms 一个协作片段，在解码/匹配内层设置检查点。单条 16 MiB 解析若不能让出，必须移到不持有 UI 会话锁的工作线程，并在完成时重验任务身份。
- 原始文本超大 Entry 使用分块读取；通配状态跨块保存，不能用固定 overlap 假装支持无限长 `*`。
- 每个 IPC 结果页最多 200 条记录，证据按页加载。后端只保留有序命中 ordinal 和扫描恢复状态，不累积全部匹配 occurrences。
- 命中 ordinal 存储上限初始定为 16 MiB（按 u64 为 2,097,152 条），达到上限停止并显示“结果过多，请缩小查询；以下为部分结果”。不偷偷丢记录或声称搜索完成。扫描器状态、临时解析树另外计入测量。
- 前端页缓存纳入现有 ProjectionBudget；清除搜索必须释放缓存。不要为模式切换复制全量结果。
- 停止保留已有结果但明确为未完成；重新点击搜索从头开始。首版不做跨应用重启恢复。
- 首批结果目标：本机 release 固定样本中头部有命中时 500 ms 内可见；取消/新输入 100 ms 内有 UI 反馈，旧任务一个协作片段后停止推进。全文件耗时取决于文件大小，不承诺瞬间完成。
- 性能数字是验收目标，不是已测结果；时间、吞吐和内存必须记录输入、构建、机器和采样方式。

## 7. 最小实现方案

### 7.1 后端

新增 `src-tauri/src/navigation_search.rs`：只负责一次文件级查询的推进、记录去重和结果分页。把任务放到已有 AppState / 文件生命周期下，不搭通用 job 系统。

复用 `search.rs` 的字段遍历、解码、span 和 literal matcher；新增有界 glob matcher。旧 `search_current` 的查询与结果协议保持兼容：它的前端校验假设 `matchEnd - matchStart == queryBytes`，不能直接塞入变长 glob 结果。

建议新增四个职责明确的 IPC 命令，具体 Rust 命名以实施时约定为准：

| 命令 | 输入 | 输出 / 行为 |
| --- | --- | --- |
| `start_navigation_search` | fileGeneration、query、syntax、representation | searchId、初始进度；替换旧查询 |
| `advance_navigation_search` | fileGeneration、searchId | 有界推进；返回 scannedThrough、命中记录数、跳过计数、状态 |
| `get_navigation_search_page` | fileGeneration、searchId、结果起点或原始 ordinal 窗口、limit | 过滤结果页或原列表窗口命中标志；有界证据 |
| `stop_navigation_search` | fileGeneration、searchId、是否释放结果 | 停止；清空时同时释放 |

请求 ID 不作为外部安全授权。所有整数、枚举、查询、分页边界在 IPC 入口校验；陈旧 fileGeneration/searchId 返回明确错误。

`fileGeneration` 仅在成功替换文件会话、关闭或失效时更新；JSONL 选择不更新。保留原有 sessionRevision 负责“当前阅读对象”的接口。新标识是为了消除已存在的文件生命周期与选择生命周期冲突。

扫描状态至少包含记录 ordinal、字段/字节位置、必要的 glob 状态。`scannedThrough` 只越过已经完整检查或已命中的记录；预算耗尽的空结果仍可继续，不能当作 EOF。

glob 使用无回溯的流式状态机，按字段重置、跨读取块保留状态，并计入 token × 字符的工作量预算。不采用 glob→不受控回溯 regex。优先复用现有源码位置与解码定位方法。

长任务不得持有全局会话锁直到扫描完成；访问安全的源快照/读取句柄，片段开始和发布前重验文件与任务身份。不得为避免借用约束复制整个已解析 Document。

### 7.2 前端

- 新增 `src/navigation-search.ts`：管理查询、searchId、显示模式、推进请求和进度。只允许一个推进请求在途；本地 epoch 拒绝晚到响应。
- `entry-list.ts` / `collection-list.ts`：在已有列表中增加结果页来源与标记渲染；保留各自分页/虚拟化，不为此次改动抽象通用列表基类。
- `main.ts`：接入文件生命周期和已有选择流程；选择变化仅更新阅读接口 revision，不重启文件搜索。打开新文件必须先隔离旧响应。
- `index.html`、`style.css`、`i18n/zh-CN.ts`、`i18n/en.ts`：增加搜索栏、模式切换、状态及键盘可访问名称。
- 模式按钮用 `aria-pressed` 或原生 radio；状态用节流的 `aria-live=polite`；命中状态有文字，不只靠颜色。窄屏导航抽屉保持原行为。
- 不自动把导航 query 注入中间搜索或 Content Viewer；“查看命中位置”只传递实际定位证据。

## 8. 实现顺序与交付门槛

### P1：搜索核心与生命周期

实现 fileGeneration、一次查询状态和普通文本 Collection / JSONL 扫描；补上同一字段跨块、预算结束继续、跳过状态及结果去重。

门槛：可搜到未加载页、长字段尾部；后台扫描期间选中其他 Entry 不改变结果、不串 session；文件切换拒绝旧结果。

### P2：完整导航交互

实现搜索栏、高亮全部、仅看匹配、进度/停止、证据、编号跳转及选择恢复。先以普通文本打通两个文件模式，不把仅 Collection 成功当作完整交付。

门槛：两种模式命中集合一致，切换不重扫；结果排序、源编号、键盘选择和阅读内容稳定。

### P3：通配符与资源边界

加入显式 glob、转义、Unicode、跨块状态、输入错误与工作预算；验证结果上限、缓存释放和无命中长扫描。

门槛：`*` 跨 chunk 不漏匹配，不跨字段/记录；病理模式可取消，UI 不被长查询阻塞。

### P4：回归、Native 验收与文档同步

完成下表；跑相关既有检查。实现完成后更新 `spec.md` §11、README 和 Native 台账，再宣称支持全文件导航搜索。本提案不提前修改现有支持声明。

## 9. 验收矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| key、深层 string、number、bool、null | 均能以内容命中记录；原始数字表示保留 |
| `\u4f60\u597d`、中文、emoji、换行 | decoded 与 raw 行为符合所选表示；高亮不切断 Unicode |
| 相同记录多次命中、重复 key | 导航仅一条记录，首个证据稳定 |
| 超出摘要、未展开节点、第 201 条、文件尾 | 不因前端未加载而漏掉 |
| 普通文本 `*`、glob `error*timeout`、`?`、转义 | 字面/通配开关清晰，跨块完整，跨字段不匹配 |
| 非法 pattern、空查询、单空格、全星号、超长查询 | 明确输入行为，无默认全量匹配陷阱 |
| 过滤第 3 条结果来自原始 Item 999999 | 打开 Item 999999，编号和内容正确 |
| 搜索期间选择 Entry、模式来回切换 | 搜索不失效、不重扫、不覆盖阅读内容 |
| 当前记录被隐藏、清除、编号跳转 | 按 §5 恢复，焦点与滚动稳定 |
| 查询 A→B、停止、重开文件、文件被改写 | A/旧文件的晚到结果不会混入 |
| JSONL 索引进行中、无命中但预算耗尽 | 显示等待/搜索中，不提前显示完成 |
| 非法 JSON / UTF-8、>16 MiB Entry | decoded 跳过原因准确；raw 可用范围准确，无混合语义 |
| 一百万项全命中、稀疏尾命中、全无命中 | 虚拟滚动、有限页缓存、可停止；内存不随累计证据线性增长 |
| 达到命中存储上限、读取失败 | 明确部分结果，不能报完整计数 |
| 带 HTML 的数据与恶意 query | 仅文本高亮，无 HTML 注入 |
| 中文输入法、键盘、窄屏、英文界面 | 可提交/清除/切换/导航，名称与焦点完整 |

验证安排：核心边界在现有 Rust 测试中增加针对性案例；新增一个导航 UI 回归脚本覆盖两列表与竞态，沿用现有 browser harness，不新增测试框架。资源上限可通过小预算注入测试，无需为了测试写超大文件。

node scripts/test-i18n.mjs
cargo test --manifest-path src-tauri/Cargo.toml --lib
